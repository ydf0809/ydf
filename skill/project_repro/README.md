# Vivado 复现与产物溯源踩坑清单

适用于主 XPR 迁移、Windows 仿真和 bit 交付。不能自动豁免时序例外，也不保证任意板卡可直接运行。

## 1. 本机能打开，移动后缺文件

- **触发**：绝对路径、中文目录、项目外文件、旧增量 DCP。
- **排查**：解析 XPR 的 File 节点及 PPRDIR/PSRCDIR 宏，核查存在且位于交付根目录。
- **用法**：可独立复制 [check_xpr.py](check_xpr.py)，执行：

~~~text
python check_xpr.py --root "<delivery_root>" --xpr "<project/main.xpr>"
~~~

- **处理/验证**：仅副本中文目录改 imported、同步引用、去掉可选增量 DCP；保留 RTL/XDC/XCI。再压缩解压、异路径仿真与重建，见 report/relocation.json。
- **边界**：检查器不解释任意 Tcl/include/readmem，必须配合真实构建。

## 2. 正 WNS 不等于完整时序签核

- **历史观察**：下层曾有正裕量，但 no_clock=2583、未约束内部端点=10627；补齐时钟后重建。历史数值不是当前结果。
- **排查**：setup/hold、DRC、no_clock、未约束内部端点、组合环、方法学和外部 I/O 延迟一起看。
- **处理**：依据实际时钟建约束；算术不达标先流水并证明数值与同步，不随意放宽约束。
- **验证**：当前构建要求 WNS/WHS≥0、DRC error=0、loops=0、no_clock=0、未约束内部端点=0，保留 I/O/CDC 等其余警告。
- **边界**：配置频率不是仪器实测，全板时序仍需外设资料和测量。

## 3. bit 存在却不是当前主工程产物

- **触发**：旧结果未清、错误 run、构建后改源、旧 manifest。
- **排查**：主 XPR/top/part、输入哈希、当次完成标记和 bit 路径；发布副本必须匹配主 run 哈希。
- **处理/验证**：开始写 building 并清旧 metrics，输入未变且工具成功才发布；verify_release.py 拒绝旧哈希、缺测试或不匹配 bit。
- **边界**：不同路径/时间重建的 bit 文件头可能不同，不要求两次 bit 全文件相等；分别溯源。

## 4. 依赖收集错导致展开失败

- **本次观察**：漏掉 compat_support，3 个上层兼容测试 module not found；首次日志保留在 sim/results/attempts。
- **排查/处理**：区分编译、展开、运行；补测试辅助模块，按实例依赖编译，不为脚本缺陷改生产逻辑。
- **验证**：退出码 0、本测试明确完成标记、无 FAIL/FATAL/ERROR 同时成立；零测试不通过。
- **边界**：当前轻量词法扫描不覆盖复杂宏、include、混合语言，必要时显式文件清单。

## 5. error/PASS 子串误判结果

- **触发**：标题含 error；或者失败前输出了局部 PASS。
- **处理**：最终通过标记配合行首错误、FAIL 和非零失败计数，不只看退出码。
- **验证**：用成功、失败、FATAL、无完成标记及非零退出码反例检查判定器，保留首次误判记录。
- **边界**：外部测试格式变更需更新规则。

## 6. Windows 启动与编码异常

- **观察**：历史出现 srcscanner、UTF-8 BOM、可选 XSim debug 异常。
- **排查**：仅在缺失时设 PROCESSOR_ARCHITECTURE=AMD64，官方 .bat 启动；检查 BOM、独立目录和相对 Tcl 入口。
- **验证/边界**：记录工具版本和首次异常。本机去掉 debug 后可用不能泛化为所有崩溃根因；不硬拼 DLL 路径。

## 7. 判定器只测到“正常输出”

- **触发**：只保留一组成功用例；标题含 `error`、失败前出现局部 PASS、完成标记缺失或工具非零退出时误判为通过。
- **排查/处理**：把判定器当作代码测试。由 `build/test_checkers.py` 固定成功、`FAIL`、`FATAL`、`ERROR`、非零失败计数、缺少完成标记和非零退出码；XPR 检查同时覆盖存在、缺失与越界引用。
- **验证**：`python build/test_checkers.py` 生成 report/checker_tests.json，记录期望/实际结果和脚本 SHA-256；`build/verify_release.py` 在脚本变化后拒绝旧结果。
- **边界**：反例只覆盖当前输出格式，工具日志格式变化时须扩展测试。

## 8. Git 换行转换使已验证文件哈希失效

- **本次观察**：暂存树对 6 个来源/适配文件转换了行尾；工作目录检查通过，不代表 Git ZIP 内仍是同一组字节。
- **排查**：比较工作目录与 Git 索引/归档字节；不能只从工作目录制作压缩包。
- **处理**：本仓库显式关闭自动换行转换，保留已登记输入、日志与报告原始字节；只更新 Git 索引，不全局改写源文件格式。
- **验证**：从 git write-tree 对应树导出 ZIP，解压后核对全部来源输入与记录的哈希，再运行真实仿真/构建。
- **边界**：修改 Git 属性或其他导出器后须重做归档检查；数值等价与字节等价是两种验收，不能混写。

## 9. 只检查路径，不执行移动后的真实构建

- **触发**：在原目录通过检查，换路径后 XPR、仿真依赖、相对脚本或归档换行才暴露问题。
- **用法**：暂存已跟踪改动后执行：

~~~text
python build/verify_relocation.py --vivado-bin "<vivado-bin>" --jobs 4
~~~

- **验证**：脚本从 Git 索引建立 ZIP，解压到其他盘符且带空格的目录，依次执行仓库检查、26 项仿真、双板主 XPR 构建和交付检查。汇总见 report/relocation.json，详细仿真见 report/relocation_simulation.json。
- **失效条件**：任一会话或工具版本变化、归档来源不是当前索引、仿真/构建/交付检查任一失败。
- **边界**：异路径 bit 不要求与原 bit 全文件相等；分别记录主 run 与 SHA-256，不据此宣称实板通过。
