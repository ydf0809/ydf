# 接口边界验证工作流

## 适用场景

适用于UART、I2C、请求/忙握手、模式切换或执行机构停止逻辑。作为工作流复制到其他题目时，应替换协议、时钟和参考结果；不依赖本项目代码。

## 提示词模板

1. 给出发送端、接收端、时钟/复位、请求有效条件和忙状态。请先写接口契约，列出未知项，不自行改变协议。
2. 根据契约列出正常输入、损坏帧、忙时新请求、连续请求、停止、复位和模式退出的参考行为。哪些结果必须等待当前事务结束，哪些可以立即取消？
3. 编写可执行测试，要求明确PASS/FAIL及超时保护。使用参考检查而非只观察波形；声明哪些真实上下游模块参与了测试。
4. 若失败，区分工具解析/展开、测试台假设、实际接口缺陷；先构造最小复现，再只改与问题直接相关的范围。
5. 重跑直接依赖测试，保留原始失败和修复后的结果；仍需说明实板差异。

## 经验与效果边界

本工程现有测试涉及板间帧解析、模式命令、I2C停止、机械臂停止等场景。本次观察到全量编译无关模块会遮蔽接口测试，所以测试入口按真实依赖隔离，并保留每项实际日志。

结果判定也属于接口契约：正常说明中的error单词不应判失败，而工具退出码0也不能掩盖测试台的FAIL。回归中机械臂上电回位检查失败，预览保留原始结果，并先确认模块/外围谁负责home脉冲，再决定后续修改。

该方法用于组织验证，不能自动证明任何协议都正确，也不能用孤立模块PASS推出完整系统PASS。电气连接、CDC约束、外设时序和执行机构响应仍须单独验证。
