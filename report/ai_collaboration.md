## 3. 本次整理的真实纠错轨迹

1. **训练校验的来源关系过时**：源包规范 COE/MEM 已统一，但 verify.py 仍将历史替代 JSON 与规范 COE 比较，且读取一个缺失的 weight_source_audit 字段。修正副本中的比较对象，补齐历史/规范两份机器可读来源审计；数值模型、生产权重和训练算法不改。
2. **上层兼容测试展开失败**：初次统一入口只扫描 RTL，漏编 compat_support。23/26 首轮结果和三个 module-not-found 日志保留在 [attempts](../sim/results/attempts/initial_snapshot_summary.json)。补齐辅助模块依赖后重新运行上层，最终状态见 [summary](../sim/results/summary.json)。不修改生产 RTL 迁就运行脚本。
3. **旧发布结果不可沿用**：原仓库 15/16 的旧测试结果不适用于新源包；旧文件先备份，之后按最终工程重新运行测试和主 XPR。最终同步后的当前集合为 23 项，查询结果必须以 [validation.md](validation.md) 为准。
4. **辅助脚本过期**：上层原始 PowerShell 入口无条件复制已不存在的 weights，并固定输出 10 个测试。仅在副本中改为目录存在才复制，并按实际测试数报告；仓库统一入口仍为 sim/run.py。

修正以文件、断言、工具日志为依据，模型答复通过可执行证据复核。历史工具配置和环境异常以可见记录进入技能，保持来源可追溯。

5. **Git 字节与工作目录不同**：发现旧换行属性会改变暂存文件，从而使来源和报告哈希在 clone/ZIP 后失效。改为保留原始字节，再从 Git 树导出 ZIP，解压核对输入哈希后开始异路径仿真与构建。此项只适配交付，不改生产逻辑。

6. **复现记录长期停留在 running**：原报告只有迁移占位，没有可重跑入口。补充 Git 索引归档与异路径检查脚本；2026-11-04 工程同步后会按当前 23 项仿真重新执行异路径构建并更新记录。

7. **设计报告补充实现依据**：在作者报告基础上，从 `xiegithub` 和既有 Codex 会话提取源码支持的事实，新增实现详解并标为技术附录，使选题问题、前序工程、逐功能处理链和发布证据形成完整对应。

8. **训练工程沉淀为可复用技能**：在 `training/scnn` 基础上新增 `skill/scnn-training-pipeline`，用配置化根目录复用参考工程，并固化成计划、映射审查、权重迁移、失败诊断、自我纠错和发布门禁六类提示词。

## 4. 实际工作流

~~~mermaid
flowchart TD
    input[读取指定工程与竞赛条款] --> contract[明确范围与验收]
    contract --> confirm[结构或接口选择由用户确认]
    confirm --> snapshot[副本与源哈希冻结]
    snapshot --> check[转换检查与定向仿真]
    check --> build[主XPR综合实现与bit生成]
    build --> evidence[报告及产物溯源]
    evidence --> relocate[压缩迁移复现]
    relocate --> local[本地提交]
    check -->|失败| diagnosis[按工具阶段定位]
    diagnosis -->|范围内修正| check
    diagnosis -->|改变算法或接口| confirm
~~~

本次由一个主智能体执行文件读取、脚本修改、测试和构建，并以可执行证据完成全过程复核。GitHub `main` 已由所有者授权发布，后续更新使用普通本地提交与快进推送。
