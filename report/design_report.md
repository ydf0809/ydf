## 1. 选题背景与解决的问题

根据现有源码和历史协作记录，本项目的实际问题可归纳为：在双板 Zynq-7000 PL 资源约束下，把摄像头、语音、图像候选搜索、SCNN 分类、目标锁定、板间通信、机械臂、底盘和显示组织成一条可执行的闭环，而不是只完成单个图像算法或单个电机控制演示。

工程实际解决的问题包括：

- 在 `600×400` 有效画面中用运动候选缩小搜索范围，再以 `128×128` ROI 进入 SCNN，避免对整幅图像持续推理。
- 将位置保持与身份分类分开：运动检测负责候选位置，SCNN 负责内容分类，调度器以 5 次分类至少 3 次阳性进入锁定，并在约 2 秒周期复检。
- 上层负责图像、语音、目标框和循迹状态，下层负责底盘、机械臂、超声波和颜色跟随；板间以 115200、8N1 UART 传输模式、传感器状态和目标框。
- 对跨域目标框采用发送端快照和接收端完整采纳，对停车、模式重入和机械臂回位定义明确事件，避免半包、旧状态和重复命令造成执行器混用。
- Python 侧提供与 RTL 通道顺序、Q12 定点、LIF 动态、脉冲编码和存储打包一致的训练、转换与数值验证工具。

源包中的直接前序工程包括上层的 `cam_lcd_voice_rz7020` 演示工程和无人机跟踪工程 `drone_cam_lcd_rz702004`。本仓库将双板协同、SCNN 推理、训练工具和发布证据整合为一条完整工程链。

可以确认的工程特点不是单一算法首创，而是系统级组合与可复现落地：

1. 运动候选、固定尺寸 ROI、脉冲神经网络分类和多状态锁定调度连接成闭环。
2. 双板按实时职责分工，并共享一套带模式、状态和原子目标框的串口协议。
3. 机械臂先调整、到达边界后由底盘辅助转向，保留执行器限位和分层控制。
4. 权重的 COE/MEM/内嵌 ROM、主 XPR、构建产物和测试证据均有哈希或日志溯源。
5. 权重 COE/MEM、内嵌 ROM、主 XPR、实现产物和测试日志形成可追溯证据链，支持从模型到比特流的完整复现。

## 3. 软硬件划分与接口

两板均为 xc7z020clg400-1，顶层分别为 top 和 super_top，计算核心以 PL RTL 实现。相机、定位、推理、通信、显示与控制部署在 FPGA，训练、微调、转换及数值校验由 Python 工具链完成。

系统约束 33.333 MHz；上层相机约束 25 MHz、SCCB 系统分频 32；下层相机约束 48 MHz。引脚及 UART 115200/8N1 见 [board](../board/README.md)，以当前 XDC/引脚报告为准。

多位框跨域采用完整快照与握手；模式/复位区分命令事件和状态值。I2C 停车等待当前事务原子完成后再发完整新包，保证执行侧收到一致的控制状态。

## 4. 模型、定位与权重

64×64×3 输入；Conv 3→8、OR pool、Conv 8→16、两次 OR pool、FC 1024→2，无 bias，3416 参数、50 步。RRGGBB 帧低字节先取形成 B/G/R 张量，0=not_drone、1=drone，平票取 0。权重 signed16 Q12、膜电位 26 位，回绕/算术移位/发放清零见 [model_spec](../training/scnn/model_spec.json)。

当前规范 COE/MEM、默认参数与实际登记的四个权重 ROM、一个参考帧 ROM 一致，见 [weight_alignment](weight_alignment.json)。转换器生成最终工程格式；新模型通过审核、相关仿真和主 XPR 重建后完成部署。

位置和身份分类职责不同。当前源码约每 2 秒复检，连续 5 个已完成的无人机计数≤10 结果可经该通道脱锁，另有丢失帧复核。软件参考覆盖从全局复位开始的一帧 50 步推理，与 RTL 的通道顺序、定点规则和脉冲动态保持一致。

## 5. 实施结果与评价维度

源包已包含 HSV 流水、相机同步、框 CDC、时钟及控制修正；本次开源整理不改变生产 RTL、引脚、时钟或阈值，只适配路径、可选增量依赖、入口和训练来源校验。

[资源汇总](resources.csv)：上层 LUT 23304、寄存器 12150、BRAM tile 109.5、DSP 0；下层 LUT 4541、寄存器 3032、BRAM tile 128、DSP 4。口径以 build/reports 实现报告为准。

本文以端到端任务闭环、双板协同、资源可部署性和证据可复现性作为评价维度。硬件侧由资源占用、WNS/WHS、DRC 和 bit 来源支撑，软件侧由参数转换、定点数值与部署一致性支撑；这些结果共同说明系统能够在当前器件约束下形成可构建、可复现的完整工程。
